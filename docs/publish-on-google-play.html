Getting Hearing Aid onto Google Play

Everything needed to take the app in this repository from a GitHub release to a public Play Store listing, including the code changes this app still needs and the forms Google asks about microphone apps.

Four things that would block this app today

  • Target API level. Since 31 August 2026, new apps must target Android 16 (API 36). The project targets API 34, so Play will reject the upload until step 2 is done.
  • Package name. The app uses com.argbyte.hearingaid. It becomes permanent the moment you upload, so change it before the first upload if you want another.
  • The word “Hearing Aid”. In many countries (the US, the EU) “hearing aid” is a regulated medical-device term. Listing the app under that name invites rejection or a request for clearance papers. Publish it as a sound amplifier with captions.
  • Where you are registered. Play Console only accepts developers in supported countries and does not serve sanctioned regions such as Iran. If that applies to you, Iranian stores like Cafe Bazaar and Myket accept the same signed app.

1Create a developer account

Sign up at play.google.com/console with a Google account you will keep for years.

2Prepare the app

Signing, the package name and the play flavor (no install permission, no network use) are already set up in the project. What remains is the target API level.

Raise the target to Android 16

Install the Android 16 SDK, then upgrade the Android Gradle Plugin to one that supports API 36 (8.10 or newer, with the Gradle version it asks for).

Terminal
sdkmanager "platforms;android-36" "build-tools;36.0.0"

Set a permanent ID and turn on signing

app/build.gradle.kts
import java.util.Properties

val keystoreProperties = Properties().apply {
    val f = rootProject.file("keystore.properties")
    if (f.exists()) f.inputStream().use { load(it) }
}

android {
    namespace = "com.hearingaid.app"
    compileSdk = 36

    defaultConfig {
        applicationId = "com.argbyte.hearingaid" // permanent once uploaded
        minSdk = 26
        targetSdk = 36
        versionCode = 1        // +1 for every upload
        versionName = "1.0.0"  // what users see
    }

    signingConfigs {
        create("release") {
            storeFile = file(keystoreProperties.getProperty("storeFile"))
            storePassword = keystoreProperties.getProperty("storePassword")
            keyAlias = keystoreProperties.getProperty("keyAlias")
            keyPassword = keystoreProperties.getProperty("keyPassword")
        }
    }

    buildTypes {
        release {
            isMinifyEnabled = true
            isShrinkResources = true
            proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"))
            signingConfig = signingConfigs.getByName("release")
        }
    }
}

3Build a signed app bundle

Play takes an Android App Bundle (.aab), not an APK. You sign it with an upload key; Google then re-signs it for users with the app signing key it keeps for you.

Terminal · only if you have no key yet (the GitHub release key in ~/.hearingaid can be your upload key)
keytool -genkeypair -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
keystore.properties · project root, never commit
storeFile=../upload-keystore.jks
storePassword=YOUR_STORE_PASSWORD
keyAlias=upload
keyPassword=YOUR_KEY_PASSWORD
Terminal · build
pwsh .\build-release.ps1
# output: dist/hearingaid-<version>-play.aab

4Create the app and its store listing

In Play Console choose Create app, set the default language, mark it as an App, Free, and accept the declarations. Then fill Grow users → Store presence → Main store listing.

5Answer the App content forms

Find these on the App content page (left menu, under Monitor and improve). Every one must be complete before any release, testing included. Suggested answers for this app:

Privacy policyRequired

The app uses the microphone, so you need a public URL. A template is below.

Data safetyNo data collected or shared

Sound is processed on the phone and never stored or sent. Settings stay on the device. Mention in the policy that captions use the phone’s speech-recognition service.

Foreground serviceMicrophone

Explain that amplification keeps running with the screen off. Add a link to a short unlisted video showing Start, screen off, and the notification.

Health appsDeclare honestly

Select the hearing and accessibility features and state the app is not a regulated medical device.

Target audience18 and over

Choosing ages under 13 brings in the Families policy and extra review.

Content ratingFill the questionnaire

No violence, gambling or user content. Expect a rating for everyone.

AdsNo ads

The app shows none.

App accessNo login needed

All features work without an account.

Privacy policy to adapt

Host it on any public page you control (GitHub Pages, Google Sites, your website). Replace the name and email.

6Run the closed test

Personal accounts created after 13 November 2023 must keep at least 12 testers opted in for 14 days in a row before production access is granted. If the count drops below 12, the 14 days start again.

7Apply for production and release

After 14 days, open Dashboard → Apply for production. Google asks how you recruited testers, what feedback you got, and what you changed. Answer specifically.

8Ship updates

For every later version: raise versionCode by one, update versionName, run pwsh .\build-release.ps1, and upload the -play.aab to the production track (or to closed testing first). Google raises the required target API level every August, so plan one update a year to stay listed for new users.
